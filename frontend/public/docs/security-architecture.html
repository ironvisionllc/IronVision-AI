2. Authentication & Authorization

2.1 JWT-Based Authentication

  • Algorithm: HS256 with 512-bit secret key
  • Token Expiration: 24 hours
  • Transport: Authorization Bearer header over HTTPS only
  • Password Storage: bcrypt with per-user salts, cost factor 12
  • Session Management: Stateless JWT — no server-side session storage

2.2 Role-Based Access Control (RBAC)

RolePermissionsScope
AdminFull CRUD, User management, Framework creationOrganization-wide
ViewerRead-only access to all compliance dataOrganization-wide

2.3 Pipeline API Authentication

  • Mechanism: API Key via X-Pipeline-Key header
  • Key Format: iv-pipe- prefix + 48 hex characters (192 bits of entropy)
  • Storage: SHA-256 hash only — raw key never stored
  • Revocation: Immediate deactivation via API
  • Usage Tracking: Count and last-used timestamp per key

3. Data Security

3.1 Data at Rest

  • Database: MongoDB with TLS connections. Atlas deployments use AES-256 encryption at rest.
  • File Storage: AWS S3 with server-side encryption (SSE-S3 / SSE-KMS)
  • Secrets: Environment variables only — never hardcoded, no defaults

3.2 Data in Transit

  • Client ↔ Server: TLS 1.3 via Cloudflare (HTTPS enforced)
  • Backend ↔ MongoDB: TLS connection strings
  • Backend ↔ AWS: HTTPS with SigV4 authentication
  • Backend ↔ LLM API: HTTPS with API key authentication

4. API Security

4.1 Input Validation

  • All endpoints use Pydantic models for request validation
  • File uploads: Type checking, size limits (50MB), filename sanitization
  • XML parsing: defusedxml library (prevents XXE attacks)
  • JSON parsing: Standard library with exception handling

4.2 CORS Configuration

Cross-Origin Resource Sharing configured per environment. Production restricts to known frontend origins.

4.3 Rate Limiting

Cloudflare WAF provides rate limiting at the edge. Pipeline API keys track usage counts for abuse detection.

5. Integration Security

5.1 Tenable VM Integration

IronVision connects to Tenable.io (Tenable Vulnerability Management) via the pyTenable SDK for automated vulnerability and compliance data ingestion.

  • Authentication: Tenable access_key and secret_key stored encrypted in MongoDB, masked in API responses
  • Export Methodology: Asynchronous Export API (Initiate → Check Status → Download) to avoid system overload
  • Delta Pulls: Stores last sync timestamp — subsequent syncs only pull new/changed data using filters.since
  • Data Scope: Vulnerability exports filter severity=[medium, high, critical], state=[open, reopened, fixed]. Compliance exports pull all configuration audit results.
  • Control Mapping: Findings auto-map to NIST 800-53 controls: vulns → SI-2/RA-5/CM-6, compliance checks → IA-2/IA-5/SC-28/AU-2/etc. via keyword matching
  • Auto-Assessment: Tenable data directly updates framework control compliance status with scan evidence
  • POA&M Generation: Non-compliant findings auto-generate Plan of Action & Milestones with severity-based timelines
  • AI Policy Generation: Critical findings trigger GPT-5.2 remediation policy generation with formal sections
  • Demo Mode: Simulated data available when no Tenable API keys are configured

5.2 OSCAL Compliance

IronVision natively supports OSCAL v1.2.1 — the NIST standard for machine-readable compliance. This enables:

  • Interoperability with FedRAMP authorization packages
  • Machine-to-machine compliance data exchange
  • Automated assessment result generation for auditors

5.3 CI/CD Pipeline Security

Compliance Gate Model: The pipeline webhook receives scan findings and evaluates them against configurable thresholds. Three policy levels (strict/default/permissive) ensure appropriate gates for different environments.

5.3 LLM Integration Security

  • AI features use the Emergent LLM Key — a managed API key with usage tracking
  • No customer data is stored by the LLM provider (stateless API calls)
  • Each AI call uses a unique session ID — no conversation persistence
  • Prompts are constructed server-side — users cannot inject into system prompts

7. Operational Security

  • Environment Isolation: Dev, preview, and production environments are fully isolated
  • Kubernetes Deployment: Container orchestration with automatic restarts and health checks
