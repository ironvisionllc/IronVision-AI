2. Authentication & Authorization

2.1 JWT Authentication

  • Algorithm: HS256, 512-bit secret
  • Expiration: 24 hours
  • Transport: Authorization Bearer over HTTPS
  • Passwords: bcrypt, per-user salt, cost factor 12

2.2 Role-Based Access Control

RolePermissionsScope
AdminFull CRUD, user management, framework creationOrganization-wide
ViewerRead-only access to all compliance dataOrganization-wide

2.3 Pipeline API Authentication

  • Mechanism: X-Pipeline-Key header
  • Key format: iv-pipe- + 48 hex chars (192 bits entropy)
  • Storage: SHA-256 hash only — raw key never stored

3. Data Security

3.1 Data at Rest

  • Database: MongoDB with TLS. Atlas: AES-256 encryption at rest
  • Files: AWS S3 with SSE-S3 / SSE-KMS
  • Secrets: Environment variables only — never hardcoded

3.2 Data in Transit

  • Client-Server: TLS 1.3 (Cloudflare)
  • Backend-MongoDB: TLS connection strings
  • Backend-AWS: HTTPS + SigV4
  • Backend-LLM: HTTPS + API key
  • Backend-Tenable: HTTPS + API key pair

4. API Security

  • Input Validation: Pydantic models on all endpoints
  • File Uploads: Type checking, 50MB limit, filename sanitization
  • XML Parsing: defusedxml (prevents XXE)
  • CORS: Restricted to known frontend origins in production
  • Rate Limiting: Cloudflare WAF at edge + API key usage tracking

5. Integration Security

5.1 Tenable VM Integration

  • SDK: pyTenable — official Tenable Python library
  • Auth: access_key + secret_key stored encrypted, masked in API responses
  • Export: Async Export API (Initiate-Check-Download) to avoid overload
  • Delta Pulls: Timestamp-tracked — only new/changed data via filters.since
  • Scope: Vulns severity=[medium,high,critical], state=[open,reopened,fixed]
  • Mapping: Findings auto-map to NIST 800-53 controls (SI-2, RA-5, IA-2, etc.)
  • Auto-Assess: Tenable data directly updates framework control compliance
  • POA&M: Non-compliant findings auto-generate milestones with severity timelines
  • Demo Mode: Simulated data when no API keys configured

5.2 OSCAL Compliance

OSCAL v1.2.1 support enables FedRAMP authorization package interoperability, machine-to-machine compliance exchange, and automated assessment result generation.

5.3 CI/CD Pipeline Security

Compliance Gate: Pipeline webhook evaluates scan findings against configurable thresholds (strict/default/permissive). Findings auto-map to framework controls.

5.4 LLM Integration Security

  • Emergent LLM Key — managed API key with usage tracking
  • No customer data stored by LLM provider (stateless calls)
  • Unique session ID per call — no conversation persistence
  • Prompts constructed server-side — no user injection
